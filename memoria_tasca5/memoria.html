1. Descripció de la pràctica

En aquesta pràctica fem servir el port sèrie perquè l'ordinador i l'Arduino es puguin passar informació. Escrivim un número al monitor sèrie de l'Arduino IDE i el led del port 13 s'encén i s'apaga tantes vegades com el número que hem escrit.

A més, l'Arduino ens contesta pel mateix monitor. Ens diu quantes vegades s'encendrà el led i, quan acaba, ens demana un altre número.

2. Material

  • Arduino UNO i cable USB
  • Protoboard
  • 1 led vermell
  • 1 resistència
  • Cables
  • Ordinador amb l'Arduino IDE (monitor sèrie)

3. Muntatge

El muntatge és el més senzill de totes les tasques: només hi ha un led amb una resistència. La pota llarga del led va al port 13 i la curta a GND. El polsador que surt a les fotos és de tasques anteriors, en aquesta no el fem servir.

4. El port sèrie: què hem après

La teoria la vam treure del PDF del port sèrie del Moodle. Aquí expliquem el que vam entendre i també el que ens va costar més.

4.1. Què és el port sèrie

Un port és la connexió entre dos aparells per passar-se informació. En un port sèrie els bits van un darrere l'altre per un sol canal, i fa falta una línia per enviar (TX) i una per rebre (RX). En un port paral·lel, en canvi, s'envien per diversos canals alhora. L'USB també és un port sèrie.

A l'Arduino UNO el port sèrie fa servir els pins 0 (RX) i 1 (TX), i mentre l'estem fent servir no podem fer servir aquests pins per a res més. Va pel mateix cable USB amb què el programem. Per veure què passa obrim el monitor sèrie de l'IDE, que té una part per escriure i enviar i una altra on surt el que ens envia l'Arduino.

4.2. Les instruccions noves

Instrucció

Què fa

Serial.begin(9600)

Engega la comunicació. El 9600 és la velocitat, en bits per segon. El monitor sèrie ha d'estar a la mateixa velocitat.

Serial.available()

Diu quants caràcters han arribat que encara no hem llegit. Si és més gran que 0, vol dir que hem escrit alguna cosa.

Serial.read()

Llegeix un sol caràcter, el primer que ha arribat.

Serial.print()

Escriu al monitor sèrie i es queda a la mateixa línia.

Serial.println()

Escriu al monitor sèrie i després salta de línia.

Serial.parseInt()

Llegeix el número sencer que hem escrit (per exemple 12) i ens el dona com a número de veritat.

 

4.3. El que més ens va costar: el codi ASCII

Primer vam fer els exemples del PDF. En el primer, la variable option guarda el que llegim amb Serial.read(). Si és una 'a' el led s'apaga i si és una 'b' s'encén. Això ho vam entendre bé.

El que ens va fer donar més voltes va ser l'exemple dels números. Quan escrivim un 5 al monitor, l'Arduino no rep el número 5, sinó el caràcter '5'. L'ordinador guarda cada caràcter amb un número de la taula ASCII, i el '5' hi val 53. Per tant, si féssim el for amb option tal com arriba, el led faria 53 pampallugues en lloc de 5.

Per això l'exemple del PDF fa option -= '0';. Com que a la taula ASCII els números van seguits, si al '5' (53) li restem el '0' (48) ens queda 5, que és el valor real.

char option = Serial.read();
if (option >= '1' && option <= '9') {
  option -= '0';
  for(int i=0;i<option;i++){ ... }

Aquí vam entendre la diferència entre posar les cometes o no: '5' entre cometes és el caràcter, que val 53, i 5 sense cometes és el número. Si al codi escrivíssim option == 5 sense cometes, no es compliria mai, perquè el que arriba és el 53.

Però aquest sistema té un problema: Serial.read() només llegeix un caràcter cada vegada. Si escrivim 12, primer llegeix el '1' i després el '2', i el led faria 1 pampallugues i després 2. Per això l'exemple només funciona del 1 al 9.

4.4. La solució que vam trobar: Serial.parseInt()

Buscant per internet vam trobar Serial.parseInt(). Aquesta funció llegeix tots els caràcters del número i ja ens dona el valor real. Si escrivim 12, ens dona 12, sense haver de restar '0' ni pensar en la taula ASCII. Així el codi queda més curt i a més funciona amb números de més d'una xifra. Per això al nostre programa vam fer servir aquesta.

5. Descripció i funcionament

5.1. El codi

int led=13;
int n=0;
int i=0;
 
void setup() {
  pinMode(led, OUTPUT);
  Serial.begin(9600);
  Serial.println("Escriu un numero:");
}
 

void loop() {
  if (Serial.available() > 0) {
    n = Serial.parseInt();
    if (n > 0) {
      Serial.print("El led s'encendra ");
      Serial.print(n);
      Serial.println(" vegades");
      for (i=0; i<n; i++) {
        digitalWrite(led, HIGH);
        delay(500);
        digitalWrite(led, LOW);
        delay(500);
      }
      Serial.println("Escriu un altre numero:");
    }
  }
}

Al setup posem el port 13 com a OUTPUT, engeguem el port sèrie a 9600 i escrivim «Escriu un numero:», perquè sapiguem que ja podem escriure.

Al loop, l'if amb Serial.available() mira si hem escrit alguna cosa. Si és que sí, Serial.parseInt() llegeix el número i el guarda a la variable n. Si n és més gran que 0, l'Arduino ens contesta amb tres instruccions seguides: el text, el número i «vegades». Les dues primeres són print perquè tot surti a la mateixa línia, i l'última és println per saltar de línia.

Després el for es repeteix n vegades: encén el led, espera 500 ms, l'apaga i espera 500 ms més. Cada pampallugues dura 1 segon. Quan acaba, ens demana un altre número. Si escrivim un 0 o una lletra, parseInt dona 0 i, com que no és més gran que 0, no passa res.

6. Opinió personal i possibles millores

En aquesta pràctica, per primera vegada, l'ordinador i l'Arduino es passen informació, i ja no només fem encendre i apagar leds. Hem après a fer servir Serial.begin, Serial.available, Serial.read i Serial.print.

El que més ens va costar va ser entendre el codi ASCII de l'exemple del PDF: que el que arriba no és el número sinó un caràcter, que '5' i 5 no són el mateix i per què s'havia de restar '0'. Hi vam donar moltes voltes. Després vam trobar Serial.parseInt(), que agafa directament el valor real i ho fa tot molt més fàcil. Tot i així, creiem que ha estat útil entendre-ho, perquè ara sabem què passa quan l'Arduino llegeix el que escrivim.

Possibles millores:

  • Que quan el número sigui 1 escrigui «vegada» i no «vegades».
  • Posar un límit, per exemple 20, perquè si algú escriu 1000 no s'hagi d'esperar més d'un quart d'hora.
  • Avisar pel monitor quan el que escrivim no és un número.
  • Fer servir el polsador que ja tenim a la protoboard perquè l'Arduino enviï un missatge a l'ordinador quan l'apretem.
